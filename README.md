# psyq-sym

Recover Psy-Q SYM debug fragments embedded in ROMs. Pure Python, no console or game facts in the decoder.

`psyq-sym --config debug-symbols.toml --version VERSION --locate` locates contiguous candidate runs. Review and save their exclusive ranges in project configuration, then omit `--locate` to emit generic schema-1 functions, structs/unions, typedefs and enums. `--records` preserves every record, including line changes, frame sizes, register masks and source offsets. Gaps and incomplete types remain explicit; names are never invented. Array dimensions are bounded by the six modifier slots in the COFF type code.

The configuration has `[abi]` with explicit `pointer_size`, `int_size`, `long_size`; each `[version.NAME]` has `rom` (relative to configuration), `address_mask`, and `ranges = [{start=..., end=...}]`. Offsets are bytes except COFF bitfields, which explicitly retain bit offsets/widths. Pointer widths use the configured ABI, not the record's referenced-type size. Anonymous tags are preserved. Equal layouts alone do not establish identity.

## Prior art and license

The original `https://github.com/sanctuary/sym` returned repository-not-found on 2026-10-18. The maintained fork `https://github.com/mefistotelis/psx_mnd_sym`, commit `546480d905779c5d40efb0d515a2b5777d616bd4`, is the golden oracle. Its UNLICENSE permits semantic ports; this repository uses the same public-domain license. The Python decoder is independently expressed from the format and that implementation. `dump.py` follows its exact DUMPSYM text spelling.

The journal's existing `dbgfuncs.py` discovery pattern was inspected and retained as reconciliation evidence, not copied as a second decoder. It incorrectly associates a length-prefixed name with the following record's address. The address is before the tag. Functions also use extended tag `0x9c`, adding floating-point register mask and signed save offset between the integer mask offset and line number. The pinned oracle does not implement `0x9c`; those records have synthetic semantic tests and optional real-ROM checks, not a claimed oracle comparison.

`tests/fixtures/build_synthetic.py` constructs invented names, paths, structures, enums and line records from the documented binary layout. `records.sym` contains only those synthetic bytes; `records.dump` is generated by the pinned oracle’s unmodified `go run ./cmd/sym_dump`. The golden test compares complete output byte for byte. Extended `0x9c` records, which the oracle does not support, are constructed and checked separately.

No cartridge bytes, ROM fragments or original developer paths/names are distributed. Optional real-ROM tests read `PSYQ_SYM_TEST_CONFIG`, a user-owned configuration in the format above, and skip when it or its ROMs are absent. Only expected ROM hashes and record counts are retained in the test code.

Run `PYTHONPATH=src python -m pytest tests`. Recreate synthetic bytes with `python tests/fixtures/build_synthetic.py`; regenerate the oracle fixture with `go run ./cmd/sym_dump /path/to/records.sym > records.dump` from the pinned fork. Runtime scanning needs no Go installation.
